What this isThe two console issues in epic #551 still marked needs-mock

A model provider is admin configuration: which service, where requests go, and which agents may use it. The credential is always each person's own. Packets B and E already approved most of the words; this packet draws every state #537 and #543 name, in the console's own look, so the two lanes can build from it.

When you approve, #537 (the provider editor for the key and endpoint kinds) and #543 (a refusal opens its own provider's door; the failure block and reauth card name the provider) lose needs-mock and can start once their dependencies land: #536 for #537; #532 and #540 for #543.

DecisionsFive, each drawn as recommended. The rest of the packet repeats what A–E approved.
  1. The kind step before #538 ships. Drawn: #537's step lists only the three kinds it builds (Anthropic API key, OpenAI API key, Your own endpoint), and #538 adds Amazon Bedrock and Claude subscription. The other option is to hold #537 until #538 is ready, so the step opens with all five at once.

    Recommended: three kinds. Each lane then ships a step that works, and no in-between state is left undrawn (your #539 rule).

  2. E7 and E9 for keys, for one person, and for nobody. Packet B worded E7 and E9 for tokens only. Drawn: the same sentences with "keys"; for one person, "The token 1 person added was given for the old address, so it is deleted. They add it again."; and when nobody has added a credential yet, Save saves with no confirm.

    Recommended: as drawn. Four new sentences, all in canon.html.

  3. Editing an existing provider. Drawn: the title is the provider's name, with its kind as a chip beside it. The provider id that the CLI and workspace pins use is made from the name at first save ("Corp gateway" becomes corp-gateway), stays fixed after that, and isn't shown in the editor. The other option is to show the id read-only under Name, which needs a new label and hint.

    Recommended: as drawn. It keeps the form to what an admin sets. The trade-off: an admin who needs the id for --model-provider has to find it outside the editor.

  4. After Save. Drawn: the editor closes back to Settings → Model providers, with the toast "Provider saved." The other option is to keep the editor open after saving.

    Recommended: close. The list row then shows the result, including the admin's own connection chip (packet A).

  5. Where a run shows its provider. Drawn: a neutral chip in the run header's chip bar, "Model provider · Corp gateway". The other option is a line in the run's summary.

    Recommended: the chip. The header bar is the one strip every run page shows at every width, and the failure block below it names the same provider.
