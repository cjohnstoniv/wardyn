# Wardyn 0.8.6 — constrained-admin mode

An adopter asked for a deployment where an administrator's own runs are governed like anyone
else's: bounded by the governance profile and capability grants that apply to them, with the
shared admin token kept as the one break-glass credential. Most of that is already true for a
browser session; this record closes the rest. It is tracked under the `0.8.6` milestone as the
epic "0.8.6: Constrained-admin mode" with three lanes, `cadm-c1`, `cadm-c2` and `cadm-c3`.

Every file:line below is `origin/main` at e0efee625 (v0.8.5).

## What is already true

- **An Admin-view browser session cannot launch.** `POST /runs` and `POST /runs/preflight` call
  `refuseAdminViewLaunch` (`internal/api/runs.go:155`, `internal/api/preflight.go:115`), which
  answers `409 admin_view` to an SSO session that is a security operator outside the user view
  (`internal/api/membermode.go:77-84`).
- **The User view is governed.** Entering it clamps the published role to `user`
  (`internal/api/membermode.go:14-19`), so `isOperator` is false and `resolveEffectiveCeiling`
  resolves the person's profile instead of short-circuiting (`internal/api/governance.go:794-830`).
- **Only the super admin short-circuits.** A security admin is already bounded at every run seam:
  `isOperator` is exactly `oidc.RoleAdmin` (`internal/api/http.go:554-565`).

## What is not

1. **Personal API tokens and the CLI.** `refuseAdminViewLaunch` lets every bearer through,
   including a `wdn_` token stamped `admin` (`internal/api/membermode.go:79`, the
   `apiTokenIDFromContext(ctx) != uuid.Nil` arm). `apiTokenAuth` publishes the token's owner with
   `withHumanIdentity` (`internal/api/apitokens.go:196-198`), so `isOperator` is true for an
   admin-role token and every run seam treats its launches as ungoverned. The CLI reads
   `WARDYN_ADMIN_TOKEN` or `WARDYN_TOKEN` (`cmd/wardyn/main.go:174`), so a personal admin token in
   CI is the same gap.
2. **The User-view type picker.** `POST /me/view` lets an admin look through any user type
   (`internal/api/user_view.go:82`, `userViewType` at `:204-222`), and a run launched in the view
   is frozen with, and resolves its profile by, the viewed type (`runCreatorUserType`,
   `internal/api/user_view.go:440-448`; the SSO lane publishes the view-aware type at
   `internal/api/http.go:439-458`). An admin can therefore choose the broadest type's profile for
   their own run.
3. **Record Mode.** `POST /workspaces/{id}/record` is `operatorOnly` (`internal/api/routes.go:443`)
   and launches an allow-all-egress, credential-injected session that deliberately skips the
   member clamp (`internal/api/workspace_run_launch.go:448-470`). It is an admin launch with no
   governance at all, by design.

## Decisions

**D1. One deployment switch, environment only.** `WARDYN_GOVERN_ADMIN_RUNS=1` turns the mode on.
It is not a console setting: a constrained admin who could reach the setting could turn it off.
The precedent is the second-human switches, which are also boot-time env and also leave the
admin token as break-glass (`docs/ENV.md:242-243`).
*Rejected:* a site-config field (writable by the person it constrains); a fourth role value in
the role map (`WARDYN_OIDC_ROLE_MAP` is env, but `/access` role mappings are console-writable,
and a fourth tier would have to be threaded through both existing predicates and every
role-stamp snapshot).

**D2. A new predicate beside `isOperator`, never a redefinition of it.**

```go
// runUngoverned: this caller's runs stand outside governance.
func (s *Server) runUngoverned(ctx context.Context) bool {
	if !s.isOperator(ctx) {
		return false
	}
	return !s.cfg.GovernAdminRuns || oidcHumanFromContext(ctx) == "" || governanceExemptFromContext(ctx)
}
```

`isOperator` also means route tier, credential namespace and run reach. Redefining it would take
the deployer funnel, the operator secret namespace and the attach rules away from an admin, none
of which the adopter asked to lose. The predicate lives in a new file
(`internal/api/govern_admin.go`), because `governance.go` is at 925 of 1000 lines.
`governanceExemptFromContext` is false until `cadm-c3` adds the recording exemption.
*Rejected:* `isOperator && !govern`, which would also govern the admin token and local mode (D3).

**D3. The admin token and local mode stay break-glass.** Neither publishes a per-human identity
(`internal/api/http.go:561-563`), so there is no person to resolve a profile for, and governing
them would leave no recovery path when SSO breaks. Every ungoverned launch under the switch is
marked on its audit row (D7). Without OIDC (local mode, or admin-token-only mode, which
`internal/api/routes.go:296` calls "local/token mode"), no request carries a person, so `isOperator`
treats every request as the admin (`internal/api/http.go:561-563`) and the switch binds nobody:
every launch is ungoverned and carries `governance_exempt`. Boot warns whenever the switch is on
and OIDC is not configured. The second-human switches warn only in local mode
(`cmd/wardynd/boot_flags.go:699-705`) because they fail closed (`503`) in token mode; this switch
fails open there, so it warns in both.
*Rejected:* refusing the admin token's launches under the switch (a lock-out with no remedy).

**D4. Personal tokens are governed, not refused.** Because `apiTokenAuth` publishes the owner,
an admin-role `wdn_` token passes through `runUngoverned` exactly like the person's session and
gets the same profile and grants. Automation keeps working, inside the person's bounds.
*Rejected:* refusing admin-role tokens at the launch doors, which breaks CI with no in-product
remedy and still leaves every other run seam ungoverned.

**D5. Under the switch, a User view through another type is a read-only preview.** The picker
stays (it is how an admin sees what a type's people see), but while the viewed type differs from
the person's stamped type (`oidc.StampedUserTypeFromContext`; an empty stamp reads as the built-in
type, the rule `runCreatorUserType` already applies), `userViewGate`
(`internal/api/user_view.go:332`) refuses every request that is not `GET`, `HEAD` or `OPTIONS`,
except the switch itself (`POST /api/v1/me/view`, already passed through at `:337`), sign-out
(`POST /api/v1/auth/logout`, `internal/api/routes.go:298`) and the policy grader
(`POST /api/v1/policies/grade`, `internal/api/routes.go:335`), a read-only computation that
persists nothing; the New Run screen's safety meter sends it on a debounce as the document is typed
(`ui/src/app/lib/api/runs.ts:356`), so refusing it would break the meter and write an
`authz.denied` row on every keystroke pause. The answer is `409` with the new reason
`user_view_preview`, audited. `POST /runs` and `POST /runs/preflight` are covered by the same rule.
This applies to security admins as well (Q-CADM1).
*Rejected:* refusing only the two launch doors, which leaves workspace onboarding, SSH-key
registration and drive writes decided under a type the person does not hold (those doors resolve
capabilities against the viewed type through `callerSubjects`); and launching silently with the
stamped type, which shows the person one type's bounds and freezes the run with another's.

**D6. Record Mode is refused under the switch, with one opt-in exemption.** A governed caller's
`POST /workspaces/{id}/record` answers `403` with the new reason `recording_governed`, before any
ceiling read or import-step claim. `WARDYN_GOVERN_ADMIN_RUNS_EXEMPT=recording` restores today's
behaviour for that lane only: the handler marks the request context exempt, so `runUngoverned`
answers true inside it and nowhere else.
*Rejected:* "governing" the record lane. It exists to run with allow-all egress and the operator's
credential injections and skips the member clamp on purpose
(`internal/api/workspace_run_launch.go:448-470`); once a profile resolves for the caller, its
fail-closed limits assertion (`:508`) refuses the lane anyway, so the honest answer is a named
refusal, not an accidental one. Refusing only open (learning) sessions was also rejected: a
confined replay carries the same operator-credential injections.

**D7. A marker, not a new action.** With the switch on, a run created ungoverned (admin token,
local mode, or the recording exemption) carries `governance_exempt: true` on its `run.create`
success row (`internal/api/runs.go:399-400`) and, for Record Mode, on `run.record.start`
(`internal/api/record.go:467`). The key is absent otherwise, so every row a deployment without the
switch writes stays byte-identical; this is the rule the `user_view` marker already follows
(`internal/api/user_view.go:450-460`).
*Rejected:* a separate audit action per exemption (a SIEM rule would have to join two actions to
see one launch).

**D8. Run-door exemptions follow the switch.** Four doors let a super admin past a run's
`deny_interactive` or `deny_ui_apps` limit. Three skip it for a super-admin role snapshot rather
than calling `isOperator`: the terminal attach's ticket lane (`internal/api/attach.go:942`), the UI
gateway (`internal/api/uigateway.go:345`) and the SSH gateway (`internal/api/sshgateway.go:308`).
The fourth is the terminal attach's no-ticket lane: `GET /runs/{id}/attach` without a ticket falls
through `ticketOrHumanAuth` to `humanOrAdminAuth` + `requireOperator`
(`internal/api/attach_ticket.go:256`), and `refuseAttachEntry`'s cookie/bearer branch
(`internal/api/attach.go:944-951`) checks only `mayEnterRun` and never reads `deny_interactive`
(`refuseInteractiveAttach` has one caller, at `:942`). A governed admin could otherwise dial their
own run with the SSO session cookie or an admin-role `wdn_` bearer and get the shell their profile
closes. Each door is reachable for a super admin only on their own run or an operator-owned one
(`mayEnterRun`, `internal/api/run_entry.go:30-32`). Under the switch, a governed admin's own run
captures a profile, so the exemption would let them shell into a run their profile closes. With the
switch on, the three stamp doors exempt only an operator-owned run (`run.OperatorOwned`), which is a
break-glass run. In the no-ticket lane, after `mayEnterRun` passes, `return false` becomes
`return !s.runUngoverned(r.Context()) && !run.OperatorOwned && s.refuseInteractiveAttach(w, r, run)`;
any helper goes in `govern_admin.go`. The admin token and local mode stay break-glass there,
because `runUngoverned` is true for them. The run-reach rule itself is unchanged.
*Rejected:* re-stamping attach tickets and SSH keys as `user` under the switch, which changes run
reach (the keep list below) to fix a governance door.

**D9. The census is enforced.** `cadm-c1` adds `TestIsOperatorCensus`, an AST scan of the
production files in `internal/api` keyed by (file, enclosing function), with an expected
`isOperator(` call count per function, following `cmd/wardynd/terminal_writer_census_test.go`. It
fails on a function not in the keep list below, or on a count that differs. A new call site must
then be classified before it merges. It is never keyed by line number: other 0.8.6 lanes edit these
files (gpat-g1 on `inline_policy.go`, deny-f2 on `sshgateway.go` and `governance_run_doors.go`, the
term-t* lanes on `attach.go`), and a line-keyed guard would make each of them fix an unrelated test.
The file:line references in the census tables are for reading at e0efee625 only.

## Data model and migrations

None. The mode adds no table and no column. A governed admin's run records its profile in the
existing `agent_runs.governance_profile_id`, as a member's does, which is what lets the run doors
(D8) and the run-limits reclamp bind it later. No migration number is taken.

## Security model

The mode changes who stands outside governance at run time, and nothing else.

- **Governed:** an SSO admin's session in either view, and any admin-role personal token, at every
  swap site above and at the four run doors.
- **Ungoverned:** the admin token and local mode (no person), and Record Mode when exempted. Each
  such launch is marked `governance_exempt` while the switch is on.
- **Unchanged:** route tiers, the credential namespace, run reach, recording reads, the deployer
  funnel, and token revocation on demotion.

### Residual risks

- **An admin still governs the governance.** Profiles, assignments, capability grants and role
  mappings are security-operator writes, and a super admin is a security operator. A constrained
  admin can therefore widen their own profile and then launch inside it. Every such write is
  audited, but the mode is not separation of duties on its own; it needs GOV4's four-eyes switch
  (`WARDYN_GOVERNANCE_SECOND_HUMAN`) beside it. The operations doc says so in one sentence.
- **Deployment-level widening stays an admin power.** Site-config SCM hosts, provider rows and
  workspace approved-egress feed every run's egress (`unionRunEgress`). The mode does not govern
  admin surfaces.
- **Self-approval.** An admin can decide approvals on their own run unless
  `WARDYN_EGRESS_SECOND_HUMAN` and `WARDYN_CAPABILITY_SECOND_HUMAN` are on.
- **The admin token is break-glass by design.** Whoever holds it runs ungoverned. The marker makes
  every such launch findable; the token must be held out of band. THREAT-MODEL.md §5 gains this as
  a sibling of "Four-eyes on egress approvals is bypassable by the admin token, by design"
  (`threatmodel/THREAT-MODEL.md:2935`).
- **The switch is deployment config.** Whoever can change the deployment's environment can turn it
  off. That is the platform team's change control, not Wardyn's.

## Upgrade and compatibility

- **Off by default, byte-identical.** With the switch unset, `runUngoverned` equals `isOperator`
  at every site and the four doors behave as today; no audit row changes shape.
- **Before turning it on**, assign admins a governance profile and the capability grants their own
  runs need, or accept that their runs fall to the deployment ceiling and to whatever enforced
  capability kinds allow. CI that launches with a personal admin token becomes governed too; move
  break-glass automation to the admin token deliberately, or grant the token's owner what it needs.
- **Rolling upgrades.** A 0.8.5 replica ignores the switch. Set it only once every replica runs
  0.8.6 (the HA recommendation, Q-HA2, is the Recreate strategy, which avoids the mixed window).
- **Runs already running** were created ungoverned and captured no profile, so the run doors stay
  no-ops for them. The switch takes effect on the next request; nobody needs to sign in again.

## Verification

- **Route matrix.** `TestAuthzMatrix` (`internal/api/authz_test.go:836`) gains two callers with
  the switch on: an SSO admin session and an admin-role `wdn_` token. Each must reach every route
  exactly as the admin does today, except `POST /workspaces/{id}/record`, which answers
  `recording_governed` once `cadm-c3` lands. The matrix proves only route admission, so it is not
  the governance proof.
- **In-handler governance.** A table test runs every swap site twice with the switch on, once as an
  SSO admin session and once as an admin-role personal token, against a profile that narrows that
  site's axis, and asserts the member outcome. The same table with the switch off asserts today's
  admin outcome. Named paths include user drives, workspace providers, owner revalidation (revive,
  restart and end extension) and preset launch.
- **Break-glass.** With the switch on, the admin token and a local-mode request launch ungoverned,
  and their `run.create` rows carry `governance_exempt: true`; with the switch off, no row carries
  the key.
- **Boot.** With the switch on and OIDC unset, boot logs the warning that the switch binds nobody.
- **Doors.** With the switch on, a governed admin's own run under a `deny_interactive` profile
  refuses attach on both the ticket lane and the no-ticket lane (SSO cookie, and an admin-role
  `wdn_` bearer dialing `GET /runs/{id}/attach` directly) and refuses SSH, and under `deny_ui_apps`
  refuses the UI gateway; an operator-owned run does not, and the admin token on the no-ticket lane
  still attaches.
- **Census.** `TestIsOperatorCensus` fails when a production `isOperator(` call is added in a
  function outside the keep list, or when a kept function's call count changes.
- **View rule.** With the switch on, a security admin and an admin each previewing another type
  get `409 user_view_preview` on `POST /runs`, `POST /runs/preflight` and a workspace create, and
  `200` on `GET` reads, `POST /me/view`, `POST /policies/grade` and sign-out. Viewing their own
  type launches.
- **Recording.** With the switch on, record answers `403 recording_governed` for an SSO admin and
  an admin-role token, and launches with `governance_exempt: true` under the exemption and for the
  admin token.
- **Docs.** `go test ./cmd/wardynd/` (the audit-actions, citation and ops-doc guards),
  `TestAuthzDeniedReasonsAreDocumented` and `scripts/test-claims-match-code.sh` pass.
