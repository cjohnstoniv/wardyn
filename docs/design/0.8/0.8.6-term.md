# 0.8.6 design: browser terminal (TERM)

Status: proposed for 0.8.6. Owner decisions Q-T1 to Q-T8 are accepted at the recommended defaults (owner ruling 2026-10-03); each carries the
recommended default the lanes build to unless it is overridden. Every file:line below is on
`origin/main` at e0efee625 (v0.8.5). The record also carries the companion run-header fix (h-h1),
which shares the console's run-detail screen but no code with the terminal lanes.

## Why

The run cockpit's terminal is the console's main way into a live sandbox, and the owner asked for
the best terminal experience we can ship. Three symptoms are reported:

- **S1.** The mouse wheel does not scroll; it sends arrow keys, so it recalls shell history instead.
- **S2.** Rendering glitches appear constantly and clear only after entering and leaving fullscreen.
- **S3.** The terminal takes keyboard focus only when the click lands on "the right spot".

Each symptom has more than one cause, spread across the sandbox images' tmux configuration, the
attach endpoint's sizing rules and the browser component's layout, focus and font handling. This
design fixes every verified cause, adds the parity features the established browser terminals
have (copy, links, flow control, a GPU renderer), and pins each fix with a test that is red on
`origin/main` and green on its lane.

## Goals and non-goals

Goals:

- the wheel scrolls tmux history in a shell and keeps sending Up/Down to full-screen programs that
  do not ask for the mouse;
- one terminal, one socket and at most one resize per real geometry change per page load;
- observers never change the writer's window size, on the web and over SSH;
- any click in the terminal area focuses it, and the panel's own buttons never strand focus;
- copying a selection works with tmux owning the mouse, without letting sandbox output write the
  user's clipboard on its own;
- cell metrics, wide characters and box-drawing glyphs render exactly;
- large output never freezes the page, and a dead writer tab stops blocking its owner's new tab
  within seconds;
- a real-tmux browser harness in the chromium gate, so these behaviours stay pinned.

Non-goals:

- **Replacing xterm.js or tmux** (decision D1).
- **Replaying history into a reattached terminal.** It was planned as T12 and cut: tmux emits
  smcup on every attach, so text written before live output lands in xterm's hidden normal buffer,
  and the current screen already repaints on reattach. After T1 the wheel reaches tmux's
  50,000-line history from a refreshed tab, which is the real need.
- **Scrolling for observers** in 0.8.6 (Q-T5).
- Changing the CLI's `wardyn run attach` client. It already sends an initial resize frame and
  SIGWINCH updates (`cmd/wardyn/attach.go:223-233`) and keeps working unchanged.

## Decisions

Each decision names the alternative it rejects.

**D1. Keep `@xterm/xterm` 6.x plus tmux, and make tmux invisible to the browser.** xterm.js is
MIT, needs no Content-Security-Policy change, and ships in VS Code, JupyterLab, Theia, Coder, ttyd
and Azure Cloud Shell. tmux gives survival across wardynd restarts and parity with the SSH gateway
for free. *Rejected:* ghostty-web 0.4 (no commits in 90 days; open accessibility, input-method,
render-loop and WASM-memory bugs; needs `data:` in `connect-src`; Coder's own switch,
coder/coder#22215, was closed unmerged on 2026-03-03); wterm (experimental); hterm (stale npm
package); a Coder-style reconnecting PTY without tmux (loses restart survival and SSH parity).
Re-evaluate if ghostty-web ships 1.0 with accessibility, key-handler and render-loop fixes and
Coder adopts it.

**D2. tmux owns the wheel: `mouse on` (Q-T1).** A plain drag becomes a tmux selection, copied
through OSC 52 (D4); Shift+drag (Option+drag on macOS) keeps xterm's native selection.
*Rejected:* Coder-style `smcup@:rmcup@` terminal overrides, which keep native selection but break
full-screen programs' repaint and the fullscreen scrolling of the coding agents that draw their
own screen.

**D3. One maintained tmux configuration, applied twice.** New images carry it in
`/etc/tmux.conf` (T1). Sandboxes already running from 0.8.5 images, and BYOI images, get the same
settings chained onto the attach command when the sandbox's `tmux -V` is 3.2 or newer (T2, Q-T2).
*Rejected:* image-only delivery (every running and BYOI sandbox keeps S1), and an unconditional
chain (an older tmux rejects unknown options and the attach must never fail because of a UX
setting). The settings are a default, not a control: sandbox code runs as the tmux owner and can
change any of them.

**D4. OSC 52 is an untrusted clipboard request; it becomes a verified copy offer the user
confirms (Q-T3).** Sandbox code can emit OSC 52 at will (`tmux set-buffer -w`), and a pane with
mouse tracking on receives the drag itself, in which case tmux copies nothing and the pane can
answer with its own payload. Measured: tmux sends `ESC]52;;<base64>` with an empty selection
field, and `@xterm/addon-clipboard` passes it through verbatim. So a payload becomes an offer only
when it equals the buffer text the user's own drag, double-click or triple-click spanned; nothing
is written until the user clicks Copy; nothing is ever read. *Rejected:* writing on any OSC 52
from the writer (lets the sandbox overwrite the clipboard); trusting "recent input" as proof of a
copy gesture (typing satisfies it); accepting only selection `c` (tmux's own copies use the empty
field); option (b), no OSC 52 at all (leaves a plain drag with no way to copy once tmux owns the
mouse).

**D5. Observers attach with tmux's `ignore-size` client flag (Q-T7).** `attach -f ignore-size`
(tmux 3.2+) removes the observer from window sizing entirely. *Rejected:* seeding the observer's
exec from a snapshot of the writer's size, which loses a measured race on tmux 3.5a (writer
120x40, observer delayed, writer resizes to 140x50, observer attaches: the window returns to
120x40).

**D6. Promotion re-attaches on the same WebSocket.** The observer exec is closed and a writer exec
(without `ignore-size`) is opened at the newcomer's size, on the same socket: one redraw, the same
on docker and k8s. A take-over still closes the displaced socket with 1008 (the
`attach_holder.go:47-50` contract, the only signal the UI uses to stop reconnecting); no in-place
demotion path is added. *Rejected:* `refresh-client -f` from the daemon, which has no
reliable client target.

**D7. The writer attaches at its real size; the client sends it.** The browser sends `?cols&rows`
on the attach URL and the server seeds the writer's `AttachOptions` from it; the post-registration
resize goes. This reverses the "size-less attach" rule at `attach.go:270-276`, which existed only
because observers could clamp the writer; D5 removes that reason. *Rejected:* keeping the sizeless
attach and resizing after registration (the 0x0 to 80x24 to real-size reflow is RC6).

**D8. Attach has two holder states, `attaching` and `ready`, and the socket reader starts before
`Runner.Attach`.** Pong and close are then processed during a slow attach, an `attaching` writer is
never probed as dead (T15), and a late session from a cancelled attach is closed by exact
identity. The reader only parses frames: control frames (resize, pong, close) are handled at once,
and input goes to a bounded queue (`attachReadLimit`; overflow closes the socket with 1009) drained
by a separate goroutine that waits for `ready` and re-checks writer authority through
`holder.writeGated` on dequeue. Input held while `attaching` is discarded when the holder was
evicted or taken over, or when Attach failed. Delivering it at `ready` preserves today's behaviour (they waited in the socket buffer, and the client's
auto-run command is sent 900ms after `onopen`, `use-attach-session.ts:305-310`). *Rejected:*
keeping the reader after `Runner.Attach` (the websocket library needs a concurrent reader to
process pong, so a registered-but-attaching writer would look dead).

**D9. The `session.attach` row is written at registration and its outcome when the attach
settles.** The audit log is append-only and hash-chained, so the outcome is a second
`session.attach` row (state `ready`, or result `failure` with the error), never an update. The
registration row exists before any take-over can be audited against it. *Rejected:* writing one
row after `Runner.Attach` returns, which lets a take-over row precede the attach it displaced.

**D10. Flow control follows ttyd.** xterm's `write(data, cb)` watermarks send `pause`/`resume`
control frames, and the server stops reading the exec hijack while paused. `pause` and `resume` join
the control frames that D8's reader handles at once, ahead of the input queue. A `pause` not
followed by `resume` within `attachWriteTimeout` ends the pump with reason `client stalled`, exactly
like a blocked write today. *Rejected:* stopping output reads
alone, because the sole reader calls `writeGated`/`Session.Write` synchronously
(`attach.go:599-634`, `attach_holder.go:190-206`), so a blocked paste would strand resume, pong
and close behind it.

**D11. GPU renderer with a safe fallback (Q-T4).** `@xterm/addon-webgl` loads after `open` only
when WebGL2 is available; context loss disposes it and falls back to the DOM renderer.
`customGlyphs` draws box-drawing and block glyphs exactly. A per-user "Terminal renderer: Auto /
GPU / Compatible" setting follows VS Code's `gpuAcceleration`. The setting is stored in the user's
browser, because renderer capability belongs to the device. *Rejected:* DOM only (RC10 stays);
GPU with no fallback (a lost context blanks a live session); a server-side preference (a new
store column, and a "GPU" choice made on one machine would follow the user to a machine where
WebGL is broken).

**D12. A test-only text-read seam before the renderer switch.** About 70 e2e and demo specs read
terminal text from the DOM, which the GPU renderer does not produce. The UI used by the e2e
backend is built with `pnpm build --mode e2e --outDir dist-e2e` and served from `ui/dist-e2e`, and
a `window.__wardynTerm` registry exists only under `import.meta.env.MODE === 'e2e'`. The e2e bundle
differs from the production bundle by exactly that guard. `ui/dist` is never produced in e2e mode,
because `make ui`, `WARDYN_E2E_NO_UI_BUILD=1` and the `ui-prebuilt` stage of
`deploy/compose/Dockerfile.wardynd` reuse it. A CI check proves the production build carries no
`__wardynTerm` symbol, and the `ui-prebuilt` stage and `make ui` output are grep-checked the same
way.
*Rejected:* a global in every build (exposes terminal contents to any script on the page);
running e2e with the DOM renderer forced (the shipped default would go untested).

**D13. One terminal per page load, and a stable host across focus mode.** The connect effect
reads `operator` and `operatorResolved` through refs, so `/me` landing never rebuilds it. Focus
mode keeps a stable host element outside the React tree, created once per run and moved with
`appendChild` between the cockpit slot and the focus overlay. Sign-out, a run-ID change and
authorisation teardown still tear down, and so does unmounting the run-detail screen (leaving
`/runs/:id` for any route), so the socket and the writer slot are never held by a detached host.
*Rejected:* a `createPortal` whose container changes,
which remounts (`ui/src/app/components/screens/run-detail/canvas.tsx:190-194` documents today's
remount and reconnect).

**D14. Fast eviction of a same-principal stale writer, never a bare promotion.** When a
same-principal web client is admitted read-only, the server pings the current writer if it is
`ready`. Two consecutive missed pings (2s each), or one unanswered ping with no PTY output for 5s,
evict it through the existing take-over path (`evictAttachHolderFor`,
`internal/api/attach_holder.go:477`): authority revoked under the registry lock, `displace()` with
a 1008 "taken over by <same principal>" close, and a `session.takeover` row. The row reuses the
existing action (`docs/AUDIT-ACTIONS.md:217`) with a new `reason` key (`stale_writer`), documented
in the same PR. *Rejected:* promoting the newcomer without evicting (two writers); a new audit
action (the existing take-over row is what reviewers already watch); waiting for the 30s ping
cycle (RC12).

**D15. Every link click is confirmed, with one narrow exemption.** `@xterm/addon-web-links` and
OSC 8 links share one navigation policy: open with `noopener,noreferrer` after a dialog that shows
the exact target URL with the host highlighted. Origins compare as full scheme, host and port,
never bare hostnames. Every target is parsed with `new URL()`; any protocol other than `http:` or
`https:` is refused with no dialog and no open; the dialog renders the normalised `url.href`
(punycode host, userinfo visible) with `url.host` highlighted. An owner-approved, compiled-in
allowlist of exact origin plus path-prefix entries (for example `https://microsoft.com/devicelogin`
and `https://github.com/login/device`) opens in one click; it compares `url.origin` plus
`url.pathname.startsWith(prefix)`, never the raw string. A host-only match is never enough, and the console's own origin is never
exempt. *Rejected:* no links (parity gap with every comparable terminal); one-click links
(terminal output is sandbox-controlled, so any link is a phishing lever); a
deployment-configurable allowlist (an admin-settable confirm bypass nobody asked for).

**D16. The web font is preloaded and cells are re-measured once it arrives.**
`document.fonts.load("13px 'JetBrains Mono'")` then nudges `term.resize(cols-1, rows)` and
`refit()`; T6's dedup keeps the PTY to at most one frame. The preload link is injected from the app
shell using Vite's `?url` import of the woff2 file. *Rejected:* `fonts.ready.then(refit)` (today;
cannot fix RC7), and a static `index.html` tag (cannot point at Vite's hashed asset).

**D17. No `aggressive-resize`.** It is a no-op under `window-size latest`. `focus-events on` is used
instead, so a writer's focus reclaims the window size.

## The tmux configuration (T1, T2)

`deploy/images/common/tmux.conf` changes:

- `set -g mouse on`, with a corrected header and rationale (the header at `:10` and the comment at
  `:12-15` contradict each other today);
- `unbind -n MouseDown3Pane` and `unbind -n M-MouseDown3Pane`, so right-click stays with the
  browser;
- `set -g set-clipboard external`, with a comment that states the truth: the sandbox can still emit
  OSC 52 itself, so the browser-side verification (T3a) is the only control;
- `set -g focus-events on`;
- `WheelUpPane`/`WheelDownPane` bindings that branch on `#{alternate_on}`, so vim, less and other
  full-screen programs that do not request the mouse get Up/Down, while a shell pane enters
  copy-mode and scrolls history.

That coding-agent image's Dockerfile copies the file. The comments above the three existing COPY lines
are corrected (`base/Dockerfile:167-168`, `aws-sso/Dockerfile:296-297`, and the same comment at
`:145-146` of the other bundled coding-agent image's Dockerfile). Boot-created sessions get
`LANG=C.UTF-8` (`deploy/images/common/agent-run-lib.sh:598`).

At attach (T2), both drivers' attach command (`docker/session.go:42`, `k8s/session.go:36-37`,
kept in lockstep as their comments require) chains the full set after `new-session -A`:
`\; set -g mouse on \; set -g set-clipboard external \; set -g focus-events on \; unbind -n
MouseDown3Pane \; unbind -n M-MouseDown3Pane \; bind -n WheelUpPane … \; bind -n WheelDownPane …`.
The chain runs only when `tmux -V`, read with a bounded read and matched by a strict
`^tmux ([0-9]+)\.([0-9]+)` regex, reports 3.2 or newer. On any mismatch the chain is skipped and
the attach proceeds as today; the bash and `sh` fallbacks stay. `focus-events` applies only to
clients attached after it is set, which the test notes. An untagged parity test asserts the chained
commands in both drivers' attach scripts equal, in order, the non-comment `set`/`unbind`/`bind`
lines of `tmux.conf`, so the two copies cannot drift from the file. T7 reuses this version gate for
the observer's `-f ignore-size`.

## Copy (T3a, T3b)

T3a adds `@xterm/addon-clipboard` ^0.2.0 with a provider whose `readText` returns `""` and which
does not answer OSC 52 queries at all, so no reply is ever typed into the PTY. `writeText` accepts
selection `''` or `'c'`, refuses `p`, `q`, `s` and digits, and never writes directly. Instead:

- **Gesture record.** The client records the last copy gesture over `.xterm-screen`: a drag (start
  and end cells), a double-click (word) or a triple-click (line). One gesture yields at most one
  offer. An OSC 52 that arrives with no gesture in the last 1s is dropped and logged.
- **Verification.** The payload becomes an offer only if it equals the xterm buffer text spanned by
  that gesture, read from `term.buffer` with trailing whitespace normalised (exactly what a tmux
  copy contains). Otherwise it is dropped, and a quiet "copy blocked: the terminal sent different
  text than you selected" notice appears.
- **Payload rules.** At most 1 MiB. Payloads with C0 control bytes other than `\n` and `\t` are
  refused.
- **The offer toast** shows the full payload in a scrollable box, with control characters and line
  breaks rendered visibly and a "contains N line breaks" flag. It never truncates. Its Copy button,
  or Cmd/Ctrl+C while the toast is focused, is the only path to `navigator.clipboard.writeText`.
- **Lifetime.** The offer is bound to this socket's writer identity and connection, and is dropped
  on a role change, a reconnect, or after 10s. A new offer never silently replaces a pending one.
  An observer socket never gets an offer.
- **Fallback.** When verification fails because the pane owns the mouse, Shift/Option+drag uses
  xterm's native selection and native copy, with no OSC 52 involved.
- `macOptionClickForcesSelection: true`.

T3a ships neutral built-in text. T3b replaces it with the platform-aware "Shift+drag"/"Option+drag"
hint and the toast text and preview format from mock packet M11, canonised in
`docs/design/terminal-escape-canon.md`.

## Client geometry, focus and rendering (T4, T5, T6, T8, T9, T10, T11, T16)

- **T4, unpadded mount.** In `attach-terminal.tsx:473-497` the padded wrapper keeps `p-1`,
  `onMouseDown` and `overflow-x-auto` and loses `containerRef`; a new unpadded child div becomes
  the xterm mount.
- **T5, focus.** (a) `e.preventDefault()` before `focus()` in the wrapper's mousedown, with the D3
  comment rewritten; (b) `focusTermIfFree()` focuses only when nothing outside the panel has focus
  (Q-T6); (c) Redraw and Fullscreen get `onMouseDown={e => e.preventDefault()}`, and Redraw
  refocuses; (d) the fullscreen hook gains an `onSettled` callback that refocuses after enter and
  exit (button, Escape or F11) and on first mount; (e) the take-over dialog's `onCloseAutoFocus`
  refocuses the terminal.
- **T6, size once.** `refit` returns early on a zero-size box and dedups on `{ws, cols, rows}`;
  `force` keeps the cols-1-then-cols nudge for Redraw. `refit()` runs synchronously after
  `term.open`. `buildWsUrl(runId, ticket?, cols?, rows?)` sends the geometry. `onopen` does a rAF
  refit without force (today it forces, `use-attach-session.ts:302`). ResizeObserver and window
  resize coalesce into one animation frame. The "SMALLEST" comment at `attach-terminal.tsx:246`
  is corrected.
- **T8, font.** D16.
- **T9, wide characters.** `@xterm/addon-unicode11` ^0.9.0, `allowProposedApi: true`,
  `term.unicode.activeVersion = "11"`.
- **T10, renderer.** D11 and D12, plus a self-hosted JetBrains Mono build that includes U+2500-259F
  (an OFL dependency, not copied code), so the DOM path is clean too. T8's preload and
  `document.fonts.load` face are repointed to the self-hosted file, and the fontsource imports at
  `attach-terminal.tsx:43-44` and their test mocks go.
- **T11, lifecycle.** D13.
- **T16, observer view.** A read-only viewer's grid is pinned to the writer's cols and rows (the
  existing `ptyCols` model, `attach-terminal.tsx:211-216,255-266`), so spectators see tmux's layout
  exactly; the holder's size already arrives in the attach-mode frame
  (`attach_holder.go:265-267`), and the grid is re-pinned on every attach-mode frame, since T7
  re-sends it on each accepted writer resize. Once T1 turns mouse reporting on, xterm's `scrollSensitivity` and
  `smoothScrollDuration` no longer affect the remote view (`smoothScrollDuration` affects only the
  local viewport, and stock sensitivity is not physical-wheel-only), so they are not tuned. The
  scroll-feel work is wheel-to-mouse-report rate limiting for trackpads: one coalesced report per
  animation frame. Coalescing accumulates wheel delta and never drops scroll distance. T16
  implements and tests that path.

New dependencies (`@xterm/addon-clipboard`, `@xterm/addon-unicode11`, `@xterm/addon-webgl`,
`@xterm/addon-web-links`, the font build) are recorded in `THIRD-PARTY-NOTICES.md` through
`scripts/third-party-notices.sh`, which CI checks.

## Server attach (T7, T14, T15)

T7 changes `internal/api/attach.go`, `attach_holder.go` and the SSH lane
(`sshgateway_channels.go:423-437`):

- **Observers** attach with `attach -f ignore-size` (D5). `runner.AttachOptions` gains
  `Observer bool`, and both drivers' attach scripts add the flag only inside T2's tmux ≥ 3.2 branch.
  An observer's exec is seeded from the writer's live registry size at admission, and every accepted
  writer resize is fanned out to every observer session's `Resize` and re-sent as an attach-mode
  frame to every observer socket. That is safe under `ignore-size`, because the window does not
  change. On tmux older than 3.2 the observer seeds from the writer's live size and re-validates
  after attach.
- **Promotion** re-attaches on the same WebSocket; a take-over still closes with 1008 (D6).
- **The writer** seeds `AttachOptions` from `?cols&rows` (D7). The post-registration resize
  (`:352-355`) is deleted, and `_ = sess.Resize` (`:618`) logs its error.
- **Docker web resizes** coalesce latest-wins off the input goroutine, on the SSH lane's model
  (`sshgateway_channels.go:281-324`).
- **Holder states** (D8): the control/input split and the bounded input queue; preparation is
  bounded; an Attach failure releases the holder; SSH promotion handles a not-yet-ready session.
- **Audit** (D9).
- The SSH lane follows the same rules, and its comments change "SMALLEST" to "latest"
  (`:424`, `:572`, and `attach.go:505`).

T15 adds the stale-writer probe (D14). T14 adds flow control (D10) on T7's control/input split;
cancellation and revocation wake paused output, and an unresumed pause ends the pump.

## Harness (T17)

A test-only WebSocket bridge to a local tmux under a PTY, so wheel, geometry, clamp and copy
behaviour are pinned in the chromium gate (`make test-e2e-ui`, `Makefile:1451`), not only in live
walks. The bridge exercises the production holder and pump logic, and it fails, never skips, when
the real-tmux fixture is required. It starts tmux with `-f deploy/images/common/tmux.conf` and the
exact attach command from `internal/runner/docker/session.go`, on a throwaway socket
(`tmux -L <random>`) killed at teardown. The bridge is a test helper behind a build tag the release

## Security model and residual risks

What is protected, and how:

- **The user's clipboard** against sandbox output. OSC 52 never writes and is never read; an offer
  must match the user's own selection, is bounded, refuses control bytes, shows the full payload,
  is bound to the writer socket and connection, and expires. Only a trusted browser action writes.
- **The user's browser** against links in output. Only parsed `http:`/`https:` targets open; every
  link is confirmed, showing the normalised URL, except exact origin-plus-path allowlist entries; the console origin is never exempt; `noopener,noreferrer`
  always.
- **The writer's session** against observers. `ignore-size` takes observers out of window sizing;
  their input and resizes are still dropped server-side (`attach_holder.go:190-206`, `attach.go:617`).
- **Write authority** across promotion, eviction and flow control. Authority is re-checked on
  dequeue of every input chunk, including input held while attaching; the input queue is bounded
  and an unresumed pause ends the pump; a take-over always closes the displaced socket; eviction
  is same-principal only, goes through the audited take-over path, and never promotes without
  evicting; an `attaching` writer is never probed.
- **The production bundle** against the test seam: the e2e bundle is built to a separate
  `dist-e2e` directory, and a CI check, the `ui-prebuilt` Dockerfile stage and `make ui` refuse a
  production bundle that contains `__wardynTerm`.
- **The developer host** against the T17 bridge: never linked into `wardynd`, loopback-only, Origin
  checked, throwaway tmux socket.
- **The daemon** against hostile `tmux -V` output: a bounded read and a strict regex; anything else
  skips the chain.

Residual risks, disclosed:

- tmux settings are a default, not a control. Sandbox code can turn the mouse off, re-enable
  `set-clipboard on`, or rebind keys; T3a's verification is the clipboard control.
- A user who selects text and confirms the offer copies what the pane displayed, the same as a
  native selection. Invisible non-control code points (bidirectional overrides, zero-width
  characters) are not C0 bytes and are not refused; how the preview shows them is a question for
  mock packet M11.
- A mouse-tracking pane can make copy fail verification (blocked notice); Shift/Option+drag is the
  fallback.
- Allowlisted device-login links open in one click by design.
- Observers cannot scroll in 0.8.6 (Q-T5).
- A same-principal tab on a link that misses two 2s pings in a row can be evicted by that
  principal's own new tab; the slow-but-alive case (pings answered at 1.5s) is pinned as not
  evicted.
- BYOI images with tmux older than 3.2, or no tmux, keep today's behaviour.

## Upgrade and compatibility

- Behaviour change for users: a plain drag now makes a tmux selection and a copy offer;
  Shift+drag (Option+drag on macOS) keeps native selection; right-click stays with the browser.
  The wheel scrolls history in a shell; full-screen programs that do not request the mouse still
  get Up/Down.
- Sandboxes already running from 0.8.5 images get the settings at their next attach (T2).
- The CLI client and SSH clients keep working unchanged; a CLI observer now also attaches with
  `ignore-size`.
- No migration, no environment change, no chart change. Rolling back the console restores 0.8.5
  terminal behaviour; sandboxes that got the T2 settings keep them until they end.
